# Gameplay parity on Horizon 26.3

This comparison covers the 59 features in the original [feasibility matrix](GAPS.md), plus behaviors found in Java code, resources and release notes. The reference release is Minecraft 26.1.2, BMH 1.9.0, tag `mc-26.1.2-v1.9.0` at `dbb60d2`. The Horizon branch also preserves newer Java sources. These add homecoming, 20 advancements and asynchronous landing searches, and remove numeric durability from normal tooltips. All four changes are included below. The Horizon baseline is `f0d56ea` with the game and mixin revisions in [compatibility.json](../../horizon/native/compatibility.json).

## Reading the baseline evidence

- **Exact** applies to the named behavior and conditions observed in a game test. A different environment or input can have separate coverage.
- **Different** identifies a concrete difference in a feature that otherwise works, or a missing part of that feature.
- **Missing** means the implementation lacks the named behavior.
- **Untested** means source or partial tests exist, but the available evidence does not establish that particular result.

The archived build passed 363 Rust tests. Its seven game-test groups contain 172 distinct passing check IDs across runs. Two grouped checks failed and subsequently passed in isolation (`n3` input lock and `cooldown1` sweep). Individual check IDs below refer to the corresponding `release-world.log`, `release-items.log`, `release-ability.log`, `release-journey.log`, `release-controls.log`, `release-sky.log` and `release-cooldown.log` under the local evidence directory `~/Library/Caches/bmh-horizon/scratch/finish-26.3/`. The grouped runs and isolated passes do not establish deterministic performance. The tested package SHA-256 was `135cc2ee30ba2e0d39d01ff9da055f8a5d9942c22d94a02eac3ad3fc619bb138`.

Most observations concern an integrated server and its local client. The second LAN client covers command permissions, points and one worn-sword test. Three dedicated-server boots cover content loading, config correction, console rules, persistence and a specific migration fixture. They provide no dedicated multiplayer combat, death, inventory, renderer or transport test. These observations establish no new result for Forge, Fabric or NeoForge. The feature implementations are in the [preserved Java sources](../../common/src/main/java/github/mrornithorynque/bmh), [native modules](../../horizon/native/mixins/bmh) and [content pack](../../horizon/content).

## Death, travel and homecoming in the baseline

| ID | Behavior | Baseline result and evidence |
|---|---|---|
| C1 | Difficulty, configured range and Eternal Items determine exile distance | **Different.** The Overworld distance in b0/b1 and changed config in l6 match. The mod counts loot slots after the host has removed vanishing items. With keep-inventory it uses a tick snapshot. The full difficulty and loadout grid was not played. |
| C2 | Choose the landing before respawn, relative to a bed, anchor or world spawn | **Different.** World spawn and invalid-point fallback passed b0, i1 and i2. The original code accepted obstructed beds/anchors and read saved spawn data. A center mismatch can fall back to vanilla or move the player after an early respawn. No archived real, charged Nether anchor run establishes 1:8 scaling and charge consumption. |
| C3 | Background search for dry, safe, in-border terrain | **Different.** b2/b3 saw one dry, grounded landing. Native reads biomes after chunk loading and uses block/collision approximations. No game sweep over oceans, border edges, Nether roof, leaves and a stalled generator. |
| C4 | Hold respawn until the search finishes | **Different.** w1 and w2 reached a distant landing. The immediate-respawn route can respawn early and relocate the player once the search finishes. An image sequence with no visible flash does not make those server transitions equivalent. |
| C5 | Hardcore death causes no exile or journey | **Untested.** Baseline checks hardcore in level.dat, treating a missing read as false. o1 tests the disabled creation button, not a real hardcore death. |
| C6 | 200 ticks of damage immunity | **Different.** c1-c3 show an ordinary hit blocked, later damage accepted, and a second death clearing immunity. The bypass check uses named damage types rather than Java's extensible tag. |
| C7 | Bell and respawn sound for nearby other players | **Different.** Native queues two playsound commands for nearby listeners. b4 only checks that a lone player generates no warning. No second listener's audio is verified. |
| C8 | Departure and arrival, with optional message | **Different.** n1/n2 measured the message with the rule on and off. The death packet can precede the mod signal. Delivery to an unmodified client, cancelled-death timing and slow network timing are unverified. |
| C9 | Exile, Far Away and tenth-death advancements | **Untested as a set.** g1/w1b observed Exile. The other two paths read the 30,000-block threshold and vanilla deaths statistic. No recorded award for either threshold. |
| C10 | Return within 24 blocks of a home snapshotted at exile | **Untested as a set.** u1-u4 observed a two-home record, a Home title and distance, Home at Last, and the text-off route. Named-point arrival, nights, a long-distance award, End exit, record migration and another listener's bell remain unverified in-game. |
| C11 | Retain Eternal Items through death | **Different.** p5-p12 verify six items, bundle contents, restart, and separation between worlds. Vanishing stacks can be discarded before the hook. A full inventory at return was not tested. |
| C12 | Remove 7% tool durability per survival death, controlled by its rule | **Different.** r5-r7 show 2,310 wear on a sword and no wear in Creative or with the rule off. The baseline skips wear with keep-inventory because the loot hook never runs. |
| C13 | Health, hunger, exhaustion and two buffs after waking | **Different.** p19/p20 show a wake with buffs and the rule-off case. The mod reads the queued player's status at the end of the server tick. Individual food bands, manual wake and actual exhaustion were not measured in-game. |
| C14 | Hide coordinates in survival and restore debug info | **Exact** for the local survival/creative/rule-off transitions in p1-p4. Restoring a preexisting true setting and mixed-mode multiplayer were not exercised. |
| C15 | Fade, night sky, star chain, message and dissolve | **Different.** n1/n2 and w1c/w2 sampled visible phases. Native draws a banded gradient and uses its own clock. Pixel-for-pixel and sound parity were not measured. |
| C16 | Black hold across loading and blocked input | **Exact** for the sampled local inputs in the isolated n3/n4 run and observed frames in w1c/w2/w4. n3 lacked enough frames in the first run. w5 ended with the death screen still open and did not prove a complete journey. Slow links, gamepads and resource reloads remain untested. |
| C17 | Music fades, star chimes and final bell | **Different.** Native fades music on its hook and plays local sounds without Java's Players sound category. The game checks measured video and state, not separate music/Players volume levels or audio timing. |

## Baseline checks beyond the original matrix

| Behavior | Evidence and remaining limits |
|---|---|
| Crafting and smithing progression | The eight recipe files match the preserved Java files. They make a vanilla bundle, a Hollow Totem, an Echo Heart, an Eternal Bundle, an amulet, and three smithing upgrades. The smithing recipe uses the active totem, a netherite tool and an echo shard. Creating the result while retaining a custom name, wear and enchantments has no archived in-game test. |
| Tool actions inherited from Minecraft | The three weapon/tool tags match. The pinned host's copper-golem handler recognizes item names ending in _axe. Scraping golems, stripping logs, unwaxing copper, pot sherds and Silk Touch, permitted enchantments, and repair through Mending lack end-to-end checks. |
| Eternal Bundle display and use counter | Java EternalBundleItem displays a numeric fullness out of 64 and the gold heavy warning, uses constant RGB 102/102/255 for its bar, shows the contents grid, and increments the used statistic after a spill. The mod's baseline bar/tooltip hooks omit the bundle. The host varies the bar color and a claimed use returns before awarding the statistic. The model for empty/filled is identical on disk. |
| Ritual and totem side effects | Java increments used on both successful wake and save. Pinned host completion of the nonconsumable Dormant Totem emits a finish vibration but does not increment its used statistic. The item activation on the successful ritual, a left-handed observer and third-person pose are separate from a successful 30-level wake. |
| Compatibility with old amulets, points and homecoming | Native code cleans legacy wear, LastUseTime, Unbreaking and Mending. It imports the Java player point list or legacy Home and an existing integrated-Java homecoming record. No archived fixture exercised these imports, preserved curses, the zero-coordinate case, or an old reading without a spawn index. |
| Java rule import coverage | Integrated y1/y2 seeds two current names, random_death_spawn_point as a byte and display_text_on_respawn as text. | Unmodified client joining, End travel and unusual modes | Java's release instructions require installation on each client. No archived handshake test covers a Horizon client missing the mod. End exit, adventure, spectator, a true hardcore world death, mixed-mode multiplayer, and same-tick deaths by two players have no general gameplay equivalence proof from these runs. |
